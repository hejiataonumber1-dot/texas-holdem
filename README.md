# Texas Hold’em

手机和电脑打开同一个网址，输入昵称、设置房间密码即可创建私人房间，或输入六位房间号和密码加入。默认无需创建授权码；只有管理员主动开启授权码模式后，创建房间才需要授权码。2～9 人，免费虚拟筹码，房主开局。无需微信账号。

包含完整 Node.js 房间服务与响应式网页，支持过牌、跟注、加注、弃牌、All-in、主池/边池结算、底牌隔离和断线重连。没有充值、支付、提现、奖金或现金结算。

## 本地运行

需要 Node.js 22 或以上。在项目目录运行：

```sh
npm ci
npm start
```

打开 http://localhost:3000 。在两个独立标签页中输入不同昵称，创建房间，再用房间号加入；不要用“复制标签页”模拟另一位玩家，这可能复制身份。手机需要公网网址，localhost 只能供本机使用。

## 上传 GitHub 后上线

GitHub 用于保存代码，GitHub Pages 只提供静态托管，不能运行多人房间服务。本项目将网页和 WebSocket 服务一起部署到 Render，部署成功后分享 HTTPS 网址即可玩，不需要单独配置前端地址。

[在 Render 部署](https://render.com/deploy?repo=https://github.com/NoRollPlz/texas-holdem)

1. 把项目代码上传到自己的 GitHub 仓库，确认仓库根目录有 package.json 和 render.yaml。
2. 登录 Render，通过上面的部署按钮或 New → Blueprint 选择仓库。
3. 检查服务为 Web Service、套餐 Free、单实例，然后创建。不要选择付费套餐。
4. 等待服务显示 Live，打开 Render 给出的实际 https://…onrender.com 地址。
5. 手机与电脑各打开网址，用两个昵称加入同一房间，确认可以开局与同步操作。

也可以使用 New → Web Service：语言 Node，构建命令 npm ci --omit=dev，启动命令 npm start，健康检查 /health，环境变量 ALLOW_GUEST=true、NODE_VERSION=22.16.0。平台提供 PORT，无需手动填写。

官方参考：[GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)、[Render Node 部署](https://render.com/docs/deploy-node-express-app)、[Render WebSocket](https://render.com/docs/websocket)。

## 管理员与创建授权码

默认允许自由创建房间，每个连接来源 15 分钟最多创建 5 次；房间密码仍独立生效。需要管理创建方式时，在服务器设置 ADMIN_USERNAME 和 ADMIN_PASSWORD（至少 6 个字符）。账号密码不要写入源码或上传 GitHub。Render 已有服务请在 Environment 中添加这两项；新 Blueprint 会要求填写这两项。未配置管理员不影响默认自由建房。

打开 /admin，登录后可设置或自动生成 8～32 个字符的创建授权码，设置有效期（1～365 天）和总建房次数（1～1,000 次）。需要限制建房时，主动开启「创建房间需要授权码」并保存创建方式；仅设置新码不会自动切换模式。关闭该开关并保存即可恢复自由创建。新码立即替换旧码；可随时停用。页面仅在设置成功后显示完整码，请自行保存并发给允许建房的朋友。授权模式下每次成功建房消耗一次；加入或观战不需要创建授权码。

创建方式、授权码校验值、有效期与使用次数保存在 ADMIN_DATA_FILE（默认 .data/admin-access.json），授权码以加盐哈希保存，文件不进入 Git。已有保存的创建方式在升级和重启时保留，旧版仅保存授权码的记录继续使用授权模式。自有服务器应挂载持久目录并备份。Render 免费实例没有持久磁盘，重启或部署后这些记录可能丢失；没有保存记录时默认恢复自由创建，需要限制时管理员应重新设置。已有房间不会因更换或停用码而中断。

可选 ROOM_CREATE_CODE 在数据文件不存在且已配置管理员时初始化授权码，并显式启用授权模式，仅建议开发测试使用；不设置该变量则默认自由创建。免费磁盘丢失后它会重新初始化并重置次数，因此正式服务不建议设置。管理员会话使用 HttpOnly / SameSite Cookie，8 小时过期；5 次失败后对应来源限制 15 分钟。管理员设置接口验证登录和请求来源。

## 使用说明

牌桌上的「表情」可以选择一位在线玩家，再选择表情并发送；也可点击玩家信息快捷指定接收者。全房间（含观众）都会看到表情从发送者飞向接收者，随后自动消失。每人两秒可发一次，仅限本房间，断线重连不重放旧表情。表情不会改变下注、筹码或行动倒计时。


牌桌顶部的「银行」可查看剩余筹码、累计借入、累计归还、未还欠款和净筹码。只有已入座、筹码为 0 且本局已结算时才能借入，每次金额等于本房间设置的初始筹码；借完后不能连续借，必须再次输光，次数不限。在「归还筹码」中按本房间初始筹码的正整数倍归还，且不能超过剩余筹码或未还欠款。「归还最多」会向下取整到可归还的最大倍数；仅能一次还清时显示「全部还清」。筹码或欠款不足一个单位时不能还款，剩余欠款继续计入最终净筹码。只能在局间操作，留房观战的原玩家也可还款。每笔还款同时减少手上筹码与欠款，净筹码保持不变；重复请求不会重复扣除。净筹码 = 剩余筹码 − 未还欠款，未还欠款 = 累计借入 − 累计归还。断线或重新入座不重置账本；结束牌桌后停止借还并固定总计，下载记录包含借还明细汇总。

房间内提供语音测试版，最多 9 人同时加入（含观众）。点击「加入语音」默认只听，不申请麦克风；点击「开麦」才请求权限，闭麦会停止麦克风轨道。收听开关与麦克风独立，可闭麦只听或两者都关闭；退出房间、断线或退出语音会关闭连接并释放麦克风。浏览器阻止自动播放时点击「播放声音」。使用 HTTPS 或本机 localhost，建议两台设备戴耳机测试。

默认通过服务器转发语音，无需额外配置 TURN；仅在显式设置 VOICE_TRANSPORT=webrtc 时使用浏览器直连与 VOICE_ICE_SERVERS。具体传输方式及限制见下文“语音连接修复（服务器转发）”。不采集视频，不录音。

本地开发设置 VOICE_TEST_MODE=true（NODE_ENV 不能是 production），用独立 ADMIN_DATA_FILE 和 ROOM_CREATE_CODE=voice-test-create 初始化测试码后，访问 /voice-self-test 运行真实双端合成音频传输、开闭麦、收听和清理测试。测试页不使用真实麦克风，不播放测试音，生产服务即使打开该变量也不提供此页面。

- 创建房间默认启用密码保护，设置 4～32 个字符的密码；关闭开关可以创建公开房间。房主将房间号或邀请链接发给朋友，并单独告知密码。
- 朋友输入昵称、房间号和密码，点击“搜索并加入房间”；错误或缺失密码会被服务端拒绝。公开房间的密码可以留空。连续 5 次失败后，同一身份需要等待一分钟再试。
- 房主在「房间设置」中可以修改或关闭密码。修改只影响后续加入者，已入座玩家与原身份重连不需要重新验证。邀请链接不包含密码，服务端仅保存加盐的密码校验值，不把密码或校验值发送给客户端。
- 至少两位有筹码的玩家可开始；每步 45 秒，超时自动过牌或弃牌。
- 房主可在局间进入「语音 / 设置 → 随机换位」发起投票，发起即算本人同意。全部在座玩家在线且至少两人时可发起，所有在座玩家同意后才随机重排；观众不参与。任一人拒绝、60 秒未全票通过、参与者掉线或座位成员变化都会取消，房主也可主动取消。投票期间暂停开下一局。换位保留筹码、借还记录、底牌和本局结果，下一局按新顺序起庄；每个人的界面仍将自己放在下方。
- 创建房间时可设置每人初始筹码，默认 2000，可填 1～1,000,000 的整数，创建后在本房间内固定。每位玩家首次入座领取该额度；输光后在局间每次借入同一额度，支持多次借入并累计记录。还款须为该额度的正整数倍（例如初始 1,000 时，只能归还 1,000、2,000、3,000……），净筹码 = 剩余筹码 − 未还欠款，允许负数。
- 局间显示本桌筹码总计，包含提前离开的玩家。同一身份重新入座恢复原有筹码与借款，刷新或重连也不会清除借款。
- 房主在局间点击「结束牌桌并总计」并确认后，所有玩家看到固定的最终总计，不能再开局、借筹码或加入。可下载文本总计记录保存；继续玩请创建新房间。
- 可以选择「以观众身份加入」，或入座后点「离座观战」留在房间。仍在参与当前手牌时，预约本局结算后自动离座；已弃牌或局间可立即离座。观众不参与发牌和行动，仅看到公共牌与正常公开的摊牌结果，可重新入座参与下一局。筹码与借款保留；最多 9 个座位、房间含观众最多 30 人。
- 所有玩家都可以在牌桌右上角点「离开房间」并确认，立即回首页并退出语音，无需房主操作。正在参与且未 All-in 的手牌自动弃牌，已下注筹码留在底池；已 All-in 的手牌继续参与本局结算。筹码和借款保留在本桌总计，本局结算后可主动重新加入恢复。房主离开后自动转交权限，最后一名成员离开后关闭房间。
- 手机支持系统分享；不支持时使用复制邀请。邀请链接会自动填入房间号。
- 身份保存在当前浏览器中；刷新、关闭后重新打开链接或在新标签页打开，都会自动恢复服务器上仍在的房间、原玩家、座位及筹码，不需要再次输入房间号和密码。新标签页接管同一身份，旧标签页停止重连。主动离开或被房主移出后，再打开只回首页；服务重启、房间过期或登录身份过期时也不能自动恢复，不会自动新建或重新加入。换浏览器、无痕模式或清除网站数据无法沿用此记录；麦克风不会自动开启。

同一房间不会创建同名玩家（忽略大小写、全角与半角及首尾空格）。游客掉线后，用原昵称与房间号重新加入可恢复原玩家的座位、底牌、筹码和累计借款；密码房间仍需验证密码。同名玩家仍在线时，会提示先关闭原窗口。公开房间的房主需使用原浏览器身份恢复；不同微信账号不会仅因昵称相同合并。

房主在「语音 / 设置 → 玩家管理」可移出在线或离线成员，操作前需要确认。被移出的在线成员回到首页并退出语音；普通未弃牌玩家按弃牌处理，已 All-in 的手牌仍参与当手结算。已投入筹码保留在底池，剩余筹码与借款保留在总计中。参与当手牌的成员需等该手结束才能重新加入；移出不是永久封禁，之后主动加入仍恢复原筹码记录。

## 部署限制

房间和身份暂存在服务内存中，服务重启或部署新版本会清空，不支持多实例。离线房主需要重新连接才能开下一局。Render 免费服务闲置 15 分钟会休眠，重新打开可能等待约一分钟；休眠或重启后请重新建房。免费服务的额度和网络可达性以实际账号及地区为准。

[Render 免费服务说明](https://render.com/docs/free)

### 创建方式、盲注和牌桌界面

管理员在 `/admin` 可切换“创建房间需要授权码”。关闭后可直接建房；加入不需要创建码。公开创建仍保留每个连接来源每 15 分钟最多 5 次、全站最多 500 个房间的限制。设置沿用管理员数据文件，兼容旧授权码记录；没有持久化磁盘的部署重启后可能恢复授权码模式。

新房间默认小盲 5、大盲 10，不收每人底注。每手开局只有小盲和大盲自动投入筹码，其他玩家轮到自己时可直接弃牌，不扣筹码；已缴的盲注在弃牌后仍留在底池。短筹码盲位只支付剩余金额，正常参与主池／边池。房主可以在两手之间修改盲注，修改后仍不收底注；小盲和大盲必须是整数，1 ≤ 小盲 ≤ 大盲 ≤ 2,000。

进入房间显示一屏牌桌和下注区。记录／总计、语音／设置使用页签、左右箭头或横向手势切换。快捷金额 ±5、±10、±50、±100 仅编辑本轮下注目标，点击确认才补齐差额；减额不会低于本轮跟注目标，加额不会超过本轮已下与剩余筹码之和。不足最低加注额时确认按钮不可用，短额 All-in 是规则允许的例外；没有重新开放加注时只能提交跟注或过牌。

发底牌或增加公共牌时播放合成音效；轮到自己超过 10 秒未操作提醒一次。可在语音／设置页关闭游戏音效，语音的麦克风和收听仍独立控制。浏览器需要先有一次点击或键盘操作才能播放音效，系统静音或后台限制可能抑制声音。

下注、跟注、加注、过牌、弃牌和 All-in 各有短提示音。服务器确认行动后，同房玩家和观众都能收到；快捷金额调整与被拒绝的操作不播放。行动序号用于去重，初次加入、刷新和重连不会重放旧操作，关闭游戏音效后也不会积攒待播放的提示。行动后立即发公共牌时，两种提示音依次播放。


### 语音连接修复（服务器转发）

语音默认通过同房间的服务器 WebSocket 转发 16 kHz 单声道 PCM，避免浏览器直连的 NAT／防火墙失败，不需要额外配置 TURN。声音不落盘；只有加入同一房间语音的成员可以发送和接收，关闭麦克风立即停止采集，关闭收听立即停止并清空排队声音。加入语音本身不会申请麦克风。

使用 HTTPS 和支持 AudioWorklet 的现代浏览器。服务器转发会增加带宽使用及网络往返延迟，Render 所在地区和用户网络会影响体验；不要把本地合成音频通过当成已经验证所有手机网络。慢连接丢弃过期语音，不积累长时间录音队列。音频每包 60 ms，正常约每秒 17 包；客户端按节奏发送并丢弃后台积压的旧帧，服务端为每个连接提供每秒 20 包的持续额度及最多 40 包的短时突发余量。超量音频直接丢弃，不逐包弹出“请求频繁”，也不占用下注、静音和退出语音的操作额度。

`VOICE_TRANSPORT=webrtc` 可恢复原先的浏览器直连方式（需要自行配置可靠 ICE/TURN）；默认不用设置此变量。AudioWorklet 参考：[MDN](https://developer.mozilla.org/en-US/docs/Web/API/AudioWorkletNode)。


### 玩家视角、筹码标记和本轮下注

玩家自己的座位固定在牌桌最下方，其余座位按实际座位顺序旋转显示，实际行动顺序保持一致。自己的下注筹码显示在底牌正上方，其他玩家的下注显示在座位附近；跟注／加注成功后产生短暂的丢筹码动画。服务端保存本轮最后一位玩家行动后的完整下注快照；换轮发牌时标记保留约 1.2 秒，公共牌翻开后再收走，期间暂不接受本机下注操作。

每局结算动画结束后，原下注位置显示带筹码图标的本局净赢输：赢显示正数、输显示负数、持平显示 0，持续到下一局开始。本局净赢输包含盲注、各轮下注及退款，区别于底池派发总额；结果由服务端固定保存，刷新或重连仍能看到，之后借筹码或离座观战不会改变它。未参与本局的观众不显示结果。

本局结束进入摊牌比牌时，所有未弃牌的比牌玩家自动向本房玩家和观众公开底牌及牌型，包含 All-in 和主池／边池的参与者。弃牌玩家，以及因其他人全部弃牌直接获胜的玩家，仍默认隐藏底牌，可在自己的底牌旁点击「亮牌给大家」自愿公开；不点击则保持隐藏。亮牌后本局内不能撤回，重连仍保留；下一局恢复隐藏。手动亮牌只能公开本人的牌，观众和牌局中途不能亮牌。

房间采用深绿毡面、金色桌边的横向牌桌。手机进入房间后强制横向显示，竖持时通过 CSS 旋转，实际横握后恢复正向显示；首页保持竖屏。全屏按钮会在浏览器允许时申请全屏和横屏方向锁，拒绝或不支持时仍保留横向牌桌。以实际可见窗口尺寸布局，并保留安全区域；紧凑的下注区固定在下方，八个快捷金额排成一行。自己的底牌位于桌子下方中央，个人筹码卡片固定在右下角；其他玩家按相对座位围桌显示，不影响实际行动顺序。记录与语音仍通过切换页查看。

输入框表示**本轮下注目标总额**：自己本轮已下 10、上家到 30，输入框显示 30，确认按钮提示补 20，服务端只扣 20。翻牌／转牌／河牌后的新下注轮次从 0 开始，可以过牌。此前轮次的投入留在底池，不加入当前目标。每手开局只由大小盲位缴纳盲注，其他玩家跟注时才投入筹码。最低合法加注仍按上一笔有效加注增量计算。

快捷按钮按面额累加，不超过全部筹码或低于需跟注金额；若草稿落在无效的加注区间，确认按钮暂时不可用，继续调整金额即可。提交时遵守最小加注和短额 All-in 规则；输入 0 只能在无需跟注时过牌。
